# 飲み忘れた分を1錠ずつ間隔をあけて飲む機能 設計書（たたき台）

- 状態: たたき台（未決事項あり）
- ブランチ: `feature/split-dose`
- 作成: 2026-11-06

## 1. 目的

飲み忘れがあって、その日に飲む錠数が2錠以上になったとき、まとめて飲まずに **1錠ずつ時間をあけて** 飲めるようにする。
Bot は1錠ごとに記録を受け付け、次の1錠の時間になったら通知する。

間隔の長さや、1日に何錠まで飲んでよいかは Bot では決めない。利用者が医師・薬剤師の指示に合わせて設定する（→ 未決事項 Q1・Q4）。

## 2. いまの動き（2026-11-06 時点の main）

- 1日の区切り（サイクル）は、定刻（`/remind_time`、本番 13:00）から次の 03:00 まで。
- 03:00 までに「完了」が押されなければ `missed_doses` が1増え、次の日の通知に「今日の分と合わせて **N錠**」と出る。
- 「完了」は1回押すだけで、その日の分を **すべて** 飲んだ扱いになり、`missed_doses` は0に戻る。
  - ログ: `taken {missed_doses: 0, prev_missed_doses: N}`
  - 記録の1行: 「前日までの分と合わせてN錠の服用を記録しました」
- 状態はログ（`data/medicine_log.jsonl`）から復元する。持ち越し錠数は「`missed_doses` を持つ最後のイベントの値」。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 合計錠数 | その日に飲む錠数。`missed_doses + 1` |
| 残り錠数 | その日の合計錠数のうち、まだ飲んでいない錠数 |
| 服用間隔 | 1錠飲んでから、次の1錠を飲めるまでの時間（設定値） |
| 次の服用時刻 | 直前の1錠を記録した時刻 + 服用間隔 |

## 4. 振る舞い（案）

### 4.1 合計1錠のとき

いまと同じ。「完了」で終わる。

### 4.2 合計2錠以上のとき

1. 定刻の通知で、合計錠数と「1錠ずつ飲む」ことを案内する。
2. ボタンは「1錠飲んだ」にする（ラベルは未決 → Q5）。
3. 押すと残り錠数を1減らし、次の服用時刻まで **未完了通知を止める**。
4. 次の服用時刻になったら「2錠目の時間です」と通知し、追いかけ通知を再開する。
5. 残りが0になったら、いまの「完了」と同じく、その日を終える（通知を消して記録を1行残す）。

```
定刻 13:00 ──[1錠飲んだ]──> 間隔待ち ──(17:00)──> 2錠目の通知 ──[1錠飲んだ]──> 完了
   │                                         │
   └ 未完了通知（retry_interval ごと）        └ 未完了通知を再開
```

### 4.3 ほかのボタンとの関係

| 操作 | 1錠目の前 | 間隔待ちの間 | 2錠目以降の通知のあと |
|---|---|---|---|
| 家に帰って飲む | いまと同じ（22時に再通知） | ボタンを出さない | 22時に再通知（Q6） |
| スヌーズ | いまと同じ | ボタンを出さない | いまと同じ |
| 取り消し | 1錠分だけ戻す（60秒以内） | ← | ← |

### 4.4 03:00 の締めで残りがあるとき（→ Q2）

案A（推奨）: 残り錠数をそのまま翌日に持ち越す。

- 例: 合計2錠のうち1錠飲んで締め → 翌日は `missed_doses = 1`（合計2錠）
- 1錠も飲んでいなければ、いまと同じく `missed_doses + 1`
- つまり「締めの時点の残り錠数 = 翌日の `missed_doses`」と定義し直す

案B: 間隔待ちの途中なら締めを延ばす。
サイクルの定義が変わり影響が大きいため、推奨しない。

### 4.5 通知文（案）

定刻（合計2錠）:
```
💊 **お薬の時間です！**
⚠️ 前日までの分を飲み忘れています。今日は **2錠** を、1錠ずつ **4時間** あけて飲みます。
1錠目を飲んだら「1錠飲んだ」を押してください。
```

1錠目を記録したとき:
```
✅ kaede が1錠目の服用を記録しました。残りは1錠です。
**17:02** に2錠目をお知らせします。
```

2錠目の時間:
```
💊 **2錠目の時間です！**
今日の残りは **1錠** です。飲んだら「1錠飲んだ」を押してください。
```

記録の1行（最後の1錠を記録したとき）:
```
📝 11/06 ✅ 2錠の服用を記録しました（13:02 kaede ／ 17:10 kaede）
```

## 5. データ

### 5.1 設定（`data/config.json`）

| キー | 型 | 既定値 | 説明 |
|---|---|---|---|
| `dose_gap_hours` | 数値（時間） | 未決（Q1） | 服用間隔 |

設定コマンド `/dose_gap hours:4` を足す（`/snooze` と同じ形）。

### 5.2 ログのイベント

いまの `taken` は「その日を終えた」意味のまま残し、途中の1錠を新しいイベントで表す。古いログはそのまま読める。

| イベント | いつ | detail |
|---|---|---|
| `dose_taken`（新） | 最後ではない1錠を記録した | `{dose: 1, remaining: 1, total: 2, next_at: "…"}` |
| `undo_dose`（新） | `dose_taken` を取り消した | `{remaining: 2}` |
| `taken` | 最後の1錠を記録した | `{missed_doses: 0, prev_missed_doses: 1, doses: [ts, ts]}` |
| `missed` | 締めで残りがあった | `{missed_doses: 残り錠数, cycle, taken_doses: 1}` |

`remaining` は `missed_doses` とは別のキーにする。`restore_state` は「`missed_doses` を持つ最後のイベント」を持ち越しの値として読むため、途中の1錠でその値を変えない。

### 5.3 復元（`replay_cycle` / `restore_state`）

その日のイベントを順に適用し、次を求める。

- `remaining`: 最後の `dose_taken` / `undo_dose` の値。なければ合計錠数
- `next_dose_at`: 最後の `dose_taken` の `next_at`。今より後なら、その時刻まで待つタスクを作り直す
- 間隔待ちのあいだに再起動したら、再起動の通知は出さず、待ちだけを引き継ぐ

## 7. テスト

- 単体（`tests/test_restore.py` に追加）
  - 1錠目のあと再起動 → 残り・次の時刻を復元する
  - 間隔待ちのあいだ追いかけ通知を出さない
  - 締めで残り1錠 → 翌日 `missed_doses = 1`
  - `undo_dose` で残りが戻る
  - `dose_taken` を含まない古いログが、いまと同じ結果になる
- 結合（偽の Discord での流れ）: 1錠目 → 待ち → 2錠目の通知 → 完了 → 記録の1行
- テスト用 Bot: ログに持ち越しを足し、服用間隔を数分にして実際に通す
