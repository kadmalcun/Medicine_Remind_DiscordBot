# 飲み忘れた分を1錠ずつ間隔をあけて飲む機能 設計書

- 状態: 実装済み・テスト用 Bot で確認中（11/6）
- ブランチ: `feature/split-dose`
- 作成: 2026-11-06

## 1. 目的

飲み忘れがあって、その日に飲む錠数が2錠以上になったとき、まとめて飲まずに **1錠ずつ時間をあけて** 飲めるようにする。
Bot は1錠ごとに記録を受け付け、次の1錠の時間になったら通知する。

想定している使い方: 本来は朝と夜に分けたいが、朝はほぼ飲めないため、いつもの 13:00 に1錠目を飲み、6時間あけて2錠目を飲む。

## 2. いまの動き（2026-11-06 時点の main）

- 1日の区切り（サイクル）は、定刻（`/remind_time`、本番 13:00）から次の 03:00 まで。
- 03:00 までに「完了」が押されなければ `missed_doses` が1増え、次の日の通知に「今日の分と合わせて **N錠**」と出る。
- 「完了」は1回押すだけで、その日の分を **すべて** 飲んだ扱いになり、`missed_doses` は0に戻る。
  - ログ: `taken {missed_doses: 0, prev_missed_doses: N}`
  - 記録の1行: 「前日までの分と合わせてN錠の服用を記録しました」
- 状態はログ（`data/medicine_log.jsonl`）から復元する。持ち越し錠数は「`missed_doses` を持つ最後のイベントの値」。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 合計錠数 | その日に飲む錠数。`missed_doses + 1` |
| 残り錠数 | その日の合計錠数のうち、まだ飲んでいない錠数 |
| 服用間隔 | 1錠飲んでから、次の1錠を通知するまでの時間。設定値 `dose_gap_hours`（既定 6時間） |
| 最終通知時刻 | 次の1錠の通知をこれより遅くしない時刻。設定値 `dose_deadline`（既定 23:00） |
| 次の服用時刻 | `min(直前の記録 + 服用間隔, 最終通知時刻)` |

## 4. 振る舞い

### 4.1 合計1錠のとき

いまと同じ。「完了」で終わる。

### 4.2 合計2錠以上のとき

1. 定刻の通知で、合計錠数と、1錠ずつ間隔をあけて飲むことを案内する。
2. ボタンは「1錠飲んだ」「まとめて飲む」「家に帰って飲む」「スヌーズ」。
3. 「1錠飲んだ」を押すと残り錠数を1減らし、次の服用時刻まで **未完了通知を止める**（間隔待ち）。
4. 次の服用時刻になったら「2錠目の時間です」と通知し、未完了通知を再開する。
5. 残りが0になったら、いまの「完了」と同じく、その日を終える（通知を消して記録を1行残す）。

```
定刻 13:00 ──[1錠飲んだ]──> 間隔待ち ──(19:00)──> 2錠目の通知 ──[1錠飲んだ]──> 完了
   │                                         │
   └ 未完了通知（retry_interval ごと）        └ 未完了通知を再開
```

### 4.3 次の服用時刻と 23:00

次の服用時刻は「直前の記録から6時間後」とし、23:00 を超えるなら 23:00 にする。
23:00 の通知では、6時間たっていなくても次の1錠を案内する。

| 1錠目を記録した時刻 | 6時間後 | 次の服用時刻 |
|---|---|---|
| 13:05 | 19:05 | 19:05 |
| 17:30 | 23:30 | **23:00**（5時間30分後） |
| 22:40 | 04:40 | **23:00**（20分後） |
| 23:20 | 05:20 | なし → 残りは翌日に持ち越す（4.4） |

23:00 以降に1錠目を記録したときは、その日の次の通知は出さず、未完了通知も止める。残りは 03:00 の締めで翌日に持ち越す。

### 4.4 03:00 の締めで残りがあるとき

残り錠数をそのまま翌日に持ち越す。「締めの時点の残り錠数 = 翌日の `missed_doses`」と定義し直す。

- 合計2錠のうち1錠飲んで締め → 翌日は `missed_doses = 1`（合計2錠）
- 1錠も飲んでいなければ、いまと同じく `missed_doses + 1`
- 合計錠数に上限は設けない

### 4.5 まとめて飲む

「まとめて飲む」を押すと、何錠飲んだかを選ぶメニューを出す（2〜残り錠数）。

- 選んだ錠数だけ残りを減らす。
- 残りが0になればその日を終える。残りがあれば、「1錠飲んだ」と同じく間隔待ちに入る。
- 合計1錠の日と、残りが1錠のときはボタンを出さない。

### 4.6 ほかのボタンとの関係

| 操作 | 1錠目の前 | 間隔待ちの間 | 2錠目以降の通知のあと |
|---|---|---|---|
| 家に帰って飲む | いまと同じ（22時に再通知） | ボタンを出さない | 出す（22時に再通知） |
| スヌーズ | いまと同じ | ボタンを出さない | いまと同じ |
| 取り消し | 記録した錠数を戻す（60秒以内） | ← | ← |

- 「家に帰って飲む」の 22時の再通知は、次の服用時刻より前なら次の服用時刻を優先する（間隔待ち中は出さない）。
- 1錠目と2錠目を別の人が押してもよい（いまと同じく誰でも押せる）。

### 4.7 通知文（案）

定刻（合計2錠）:
```
💊 **お薬の時間です！**
⚠️ 前日までの分を飲み忘れています。今日は **2錠** を、1錠ずつ間隔をあけて飲みます。
1錠飲んだら「1錠飲んだ」を押してください。
```

1錠目を記録したとき:
```
✅ kaede が1錠目の服用を記録しました。残りは1錠です。
**19:05** に2錠目をお知らせします。
```

2錠目の時間:
```
💊 **2錠目の時間です！**
今日の残りは **1錠** です。飲んだら「1錠飲んだ」を押してください。
```

23:00 以降に1錠目を記録したとき:
```
✅ kaede が1錠目の服用を記録しました。残りの1錠は、明日の分と合わせてお知らせします。
```

記録の1行（その日を終えたとき）:
```
📝 11/06 ✅ 2錠の服用を記録しました（13:05 kaede 1錠 ／ 19:10 kaede 1錠）
```

## 5. データ

### 5.1 設定（`data/config.json`）

| キー | 型 | 既定値 | 設定コマンド | 説明 |
|---|---|---|---|---|
| `dose_gap_hours` | 数値（時間） | 6 | `/dose_gap hours:6` | 服用間隔 |
| `dose_deadline` | `HH:MM` | `23:00` | `/dose_deadline time:23:00` | 次の1錠の通知をこれより遅くしない |

定刻（13:00）は既存の `remind_time` をそのまま使う。

### 5.2 ログのイベント

いまの `taken` は「その日を終えた」意味のまま残し、途中の記録を新しいイベントで表す。古いログはそのまま読める。

| イベント | いつ | detail |
|---|---|---|
| `dose_taken`（新） | 残りが0にならない記録 | `{count: 1, remaining: 1, total: 2, next_at: "…" または null}` |
| `undo_dose`（新） | `dose_taken` を取り消した | `{remaining: 2}` |
| `taken` | 残りが0になった記録 | `{missed_doses: 0, prev_missed_doses: 1, count: 1}` |
| `undo_taken` | `taken` を取り消した | `{missed_doses: 1, remaining: 1}` |
| `missed` | 締めで残りがあった | `{missed_doses: 残り錠数, cycle, taken_doses: 1}` |

`remaining` は `missed_doses` とは別のキーにする。`restore_state` は「`missed_doses` を持つ最後のイベント」を持ち越しの値として読むため、途中の記録でその値を変えない。

### 5.3 復元（`replay_cycle` / `restore_state`）

その日のイベントを順に適用し、次を求める。

- `remaining`: 最後の `dose_taken` / `undo_dose` / `undo_taken` の値。なければ合計錠数
- `next_dose_at`: 最後の `dose_taken` の `next_at`。今より後なら、その時刻まで待つタスクを作り直す。`null` なら締めまで待つ
- 間隔待ちのあいだに再起動したら、再起動の通知は出さず、待ちだけを引き継ぐ
- その日の合計錠数は、その日が始まる前の持ち越し（`carried_doses(events, start)`）から求める。ログ全体の最後の値は、その日の「完了」で0になっているため使わない。締めのときに止まっていて、前日分の `missed` を遅れて記録した場合も、`detail.cycle` が前日なら持ち越しに数える

## 7. テスト

- 単体（`tests/` に追加）
  - `next_dose_time`: 4.3 の表の4行
  - 1錠目のあと再起動 → 残り・次の時刻を復元する
  - 間隔待ちのあいだ未完了通知を出さない
  - 締めで残り1錠 → 翌日 `missed_doses = 1`
  - `undo_dose` で残りが戻る
  - まとめて2錠（合計3錠）→ 残り1錠で間隔待ち
  - `dose_taken` を含まない古いログが、いまと同じ結果になる
- 結合（偽の Discord での流れ）: 1錠目 → 待ち → 2錠目の通知 → 完了 → 記録の1行
- テスト用 Bot: ログに持ち越しを足し、服用間隔を数分にして実際に通す

## 10. 確かめたいこと

- 23:00 以降に1錠目を記録した場合（4.3 の表の4行目）、「その日は次の通知を出さず、翌日に持ち越す」と解釈した。23:00 を過ぎていても、すぐ（または数分後に）2錠目を通知したい場合は変える。
